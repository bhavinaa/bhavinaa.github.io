Preflight — Pre-launch LLM Safety Audit

Python Eval harnesses LLM APIs
View on GitHub

The problem

Before a model ships, someone needs to know how it behaves under adversarial pressure — not just whether it refuses obviously bad requests, but how it holds up against the subtler ways people try to get around policy. Doing that by hand doesn't scale, and ad hoc test scripts aren't reproducible enough to trust.

What I built

Preflight is an evaluation harness that takes a policy document as input, generates adversarial test suites from it, runs them against a target model through its API, and scores each response by severity tier. Every run is fully reproducible: fixed-config replay and full input/output provenance mean two people running the same suite get the same result, and every score can be traced back to the exact prompt and response that produced it.

I also built a moderation-queue simulator alongside it, modeling backlog growth, reviewer disagreement rates, and how often appeals get overturned — the parts of a safety pipeline that happen after the model responds.

Validating it actually works

A severity classifier is only useful if it's calibrated. I validated it against a hand-labeled golden set of roughly 200 cases, reporting precision and recall per severity tier along with a written error analysis of where the classifier disagreed with human labels and why.

A safety tool that can't be audited itself isn't a safety tool — it's a black box with good intentions.

What I'd extend next

  • Widen the attack-vector coverage beyond the current four categories.
  • Add inter-rater agreement scoring to the golden set itself, not just model-vs-label agreement.
  • Build a lightweight dashboard so results are readable without digging through raw provenance logs.
